# Lagoon 1.0 Release Readiness, Feature, and App Store Audit

Audit date: August 26, 2026

## Executive summary

Lagoon is a strong, unusually ambitious feature-complete beta. The playback stack, Apple-platform integration, Home discovery, Seerr support, and Apple TV Top Shelf experience make it genuinely distinctive among Jellyfin clients.

It should not be submitted as version 1.0 yet. The primary blockers are distribution, privacy, licensing, and validation rather than missing core movie and television functionality.

The most important concerns are:

1. Missing privacy manifests and local-network permission description.
2. Unresolved licensing obligations for FFmpeg and the statically linked MPVKit-derived libraries.
3. No published privacy policy, support page, third-party acknowledgements, or in-app legal links.
4. OpenSubtitles API and distribution terms need to be settled.
5. A currently failing tvOS UI regression and five Swift concurrency warnings.
6. No external TestFlight or physical-device compatibility matrix.
7. No signed App Store archive and upload validation yet.

## Audit snapshot

This audit covers the current working tree, including source, tests, Xcode configuration, dependencies, documentation, storage and network behavior, and player negotiation.

- Current commit at time of audit: `1bbd949`

- Approximate Swift source size: 40,000 lines
- Unsigned Release size: 27 MB on iOS and 28 MB on tvOS
- Fresh unsigned Release builds: passed for iOS and tvOS
- Unit tests: 295 tests in 27 suites, all passed
- App executable coverage: 18.13%
- Selected deterministic tvOS UI tests: three of four passed
- Release-build warnings: five Swift concurrency warnings

The working tree also contained uncommitted Collections work at the time of the audit, including [CollectionDetailView.swift](../Lagoon/Views/Detail/CollectionDetailView.swift), [CollectionDiscovery.swift](../Lagoon/Views/Home/CollectionDiscovery.swift), and collection tests. Collections are therefore treated as in-development rather than released functionality in this report.

The one UI test failure appears to be an outdated test assumption. It permits twelve downward focus moves before looking for the first plugin row, while Home settings now contain fifteen native rows. This probably is not a product focus failure, but the regression test needs updating and the length of that settings screen deserves a UX review.

## Player support

Lagoon does not use AVPlayer, VLC, or libmpv for primary playback. It has a bespoke pipeline implemented around [SampleBufferPlayerEngine.swift](../Lagoon/Views/Player/SampleBuffer/SampleBufferPlayerEngine.swift):

```text
Jellyfin/HTTP
    -> libavformat demux
    -> VideoToolbox, dav1d, or software decode
    -> AVSampleBufferDisplayLayer
    -> AVSampleBufferAudioRenderer
    -> synchronized Apple media presentation
```

That architecture gives Lagoon a rare combination: FFmpeg-level container flexibility with native Apple media integration.

### Negotiated playback modes

- Direct play
- Direct stream/remux
- Jellyfin HLS/fMP4 transcoding
- Automatic fallback from direct play to stream copy and finally transcode
- Resume preservation through fallbacks
- Sparse on-disk HTTP range cache
- Pre-caching of the next episode

### Video

Implemented negotiation covers:

- Containers: MKV, WebM, MP4, M4V, MOV, AVI, MPEG, TS/M2TS, and VOB
- H.264
- HEVC Main/Main10
- HDR10, HLG, and HDR10+
- Multiple Dolby Vision profiles, with profile 7 base-layer fallback
- AV1 Main, including 10-bit and HDR variants
- VP9 profiles 0 and 2
- VC-1
- MPEG-2
- MPEG-4 Part 2
- Anamorphic and non-square-pixel content

Important qualifications:

- AV1 software fallback is capped at 1080p.
- VP9 and legacy software paths are generally capped at 1080p.
- Interlaced content is sent to transcoding; there is no local deinterlacer.
- These are code-supported profiles, not yet a complete device-by-device certification matrix.

### Audio

- AAC and MP3
- AC-3 and E-AC-3
- E-AC-3 JOC/Atmos where Apple accepts `ec+3`
- DTS
- TrueHD
- FLAC
- Opus and Vorbis
- PCM variants
- ALAC in appropriate containers
- Multichannel software decoding to LPCM
- Audio-track and preferred-language selection
- Audio delay
- Stereo spatial audio where supported

TrueHD Atmos objects and DTS:X metadata are not preserved. Those formats become multichannel LPCM. That is broadly comparable to the restrictions documented by [Infuse's audio support](https://support.firecore.com/hc/en-us/articles/217735707-Audio-Options-Capabilities).

### Subtitles

- SRT/SubRip

ASS support is substantial but does not provide full libass parity. Complex typography, embedded fonts, karaoke effects, and some advanced positioning can differ.

### Playback experience

- Frame-rate and dynamic-range matching on Apple TV

- Chapters

### Not currently supported

- Live TV or DVR
- Offline downloads

- Manual streaming quality or bitrate selection

## What is special compared with other clients?

The standout is not merely broad codec support. It is the combination of:

- FFmpeg demuxing and software fallbacks
- Native Apple sample-buffer presentation
- Frame-rate and dynamic-range matching
- Picture in Picture, AirPlay, system media controls, and background playback
- Rich Seerr administration
- Curated native Home discovery
- A composed, credential-free Top Shelf experience

Swiftfin generally separates broad VLC compatibility from AVPlayer's better Apple integration. Lagoon attempts to provide both categories through one player. That is technically compelling, although it also gives Lagoon a larger bespoke player surface that needs more real-world testing.

## Competitor comparison

This comparison is based on current public documentation and release notes as of the audit date, not a hands-on codec shootout.

### Swiftfin

[Swiftfin](https://github.com/jellyfin/Swiftfin) is the official native Swift Jellyfin project. Its documented players split capabilities between VLCKit and native AVPlayer: VLC provides broader playback controls and formats, while AVPlayer provides Picture in Picture, AirPlay, TLS 1.3, and frame-rate matching. See its [player comparison](https://github.com/jellyfin/Swiftfin/blob/main/Documentation/players.md) and [library support](https://github.com/jellyfin/Swiftfin/blob/main/Documentation/libraries.md).

Lagoon advantages:

- One integrated compatibility and native-system player path
- Seerr/Jellyseerr support
- Richer curated Home
- More developed Top Shelf
- Strong subtitle acquisition workflow
- More detailed request administration

Swiftfin advantages:

- Official Jellyfin project status
- Larger established open-source ecosystem
- iOS 16 support rather than iOS 26 only
- Live TV on supported platforms
- More Jellyfin library types
- User-configurable playback profiles

Swiftfin's current tvOS release work is still publicly tracked in its [tvOS status discussion](https://github.com/jellyfin/Swiftfin/discussions/1294).

### Streamyfin

[Streamyfin](https://github.com/streamyfin/streamyfin) is a cross-platform Expo/React Native client using MPV/MPVKit, with current tvOS releases documented on its [release page](https://github.com/streamyfin/streamyfin/releases).

Lagoon advantages:

- More Apple-native playback architecture
- Frame and dynamic-range matching integrated with the main player
- Deeper Seerr request state and administration
- More bespoke Home discovery
- Particularly strong Top Shelf artwork composition

Streamyfin advantages:

- Offline downloads
- Android and Chromecast
- More languages
- Larger plugin and settings ecosystem
- Session administration and broader server integrations
- Greater cross-platform reach

### Infuse

[Infuse](https://apps.firecore.com/infuse-pro) remains the benchmark for mature Apple playback. It supports more Apple platforms, more languages, downloads, NAS and cloud sources, Trakt, optical-disc formats, deinterlacing, and years of device-specific refinement. Its supported formats are documented by [Firecore](https://support.firecore.com/hc/en-us/articles/360045051934-What-is-Infuse).

Lagoon advantages:

- Jellyfin-first rather than a generic media frontend
- Integrated Seerr request workflow
- Jellyfin-native watched state, Favorites, Next Up, and server state
- No separate paid Pro codec tier currently
- More control over Jellyfin playback negotiation
- Curated Jellyfin discovery and administration

Infuse advantages:

- Playback maturity and field coverage
- Offline downloads
- Deinterlacing
- More sources and platforms
- Localization and accessibility maturity
- Trakt and extensive metadata integrations
- Broader format and disc-image support

### Official Jellyfin iOS app

The [official Jellyfin iOS client](https://github.com/jellyfin/jellyfin-ios) is primarily an Expo/React Native wrapper around the Jellyfin web experience, with native enhancements. It has no equivalent official tvOS app.

Lagoon is much more native and playback-focused, but the official client inherits more of the web client's broad server functionality and supports older OS versions.

The official list of available Jellyfin clients is maintained on the [Jellyfin client downloads page](https://jellyfin.org/downloads/clients/?platform=iOS%2CtvOS).

## Apple guideline assessment

### What already looks good

- Lagoon is a substantial native app, not a repackaged website. It clearly satisfies Apple's minimum-functionality concern.
- It uses public Apple APIs and does not download executable code.
- The app's own name, icon, and interface are distinct.
- Authentication is necessary to access the user's Jellyfin server.
- Sign in with Apple should not be required because this is a client for a specific third-party service, covered by the service-client exception in section 4.8.
- The app does not create Jellyfin accounts, so Apple's in-app account-deletion requirement should not apply.
- There are no purchases or feature unlocks, so In-App Purchase is not currently needed.
- Background audio is tied to legitimate media playback.
- Tokens and sessions use Keychain.
- No analytics, advertising, tracking, or obvious credential logging was identified.
- The Top Shelf extension receives cached artwork and metadata, not account credentials.
- iPhone and iPad support are built into the same target.
- The app does not provide or advertise public media sources.

These conclusions align with Apple's current [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).

### Submission blockers and gaps

#### 1. Privacy manifests

There is no `PrivacyInfo.xcprivacy` in the app or Top Shelf extension. The code uses required-reason APIs, and Apple has rejected uploads missing valid reasons since May 2024. See Apple's [required-reason API guidance](https://developer.apple.com/documentation/bundleresources/describing-use-of-required-reason-api).

The likely declarations are:

| API category | Likely reasons |
| --- | --- |
| UserDefaults | `CA92.1` for app-only preferences |
| App-group UserDefaults | `1C8F.1` |
| System uptime | `35F9.1` |
| Available disk space | `E174.1` |
| File timestamps | `C617.1` |

These must be verified against actual uses. The Top Shelf extension needs its own containing-bundle manifest for app-group UserDefaults.

#### 2. Local-network permission

`NSAllowsLocalNetworking` is present, but `NSLocalNetworkUsageDescription` is absent. Apple requires a clear purpose string for local-network access. See [`NSLocalNetworkUsageDescription`](https://developer.apple.com/documentation/bundleresources/information-property-list/nslocalnetworkusagedescription).

Suggested text:

> Lagoon connects to Jellyfin and Seerr servers on your local network to browse and play your media.

#### 3. Privacy policy and in-app access

Apple requires an iOS privacy-policy URL and tvOS privacy-policy text. The policy must also be easily accessible inside the app. About currently contains version and server information but no privacy, support, or legal links. See Apple's [app privacy requirements](https://developer.apple.com/help/app-store-connect/manage-app-information/manage-app-privacy/).

The policy should explain:

- Jellyfin, Seerr, and OpenSubtitles connections
- On-device server labels, preferences, recent searches, and caches
- Keychain token storage
- Top Shelf app-group metadata and artwork
- OpenSubtitles title, episode, media-ID, hash, size, and credential flow
- Retention and deletion
- Plain-HTTP server risks
- No developer analytics, advertisements, or tracking, if that remains true

Data Not Collected may be a valid App Store privacy answer because Lagoon has no developer backend, but only after confirming OpenSubtitles retention and Apple's definition of collection. Do not select it on assumption alone. Apple explains the definition on its [privacy-details page](https://developer.apple.com/app-store/app-privacy-details/).

#### 4. Third-party licensing

The binary package in [Package.swift](../Packages/LagoonFFmpeg/Package.swift) includes FFmpeg 8.1.2 and binary dependencies from MPVKit: GnuTLS, GMP, nettle/hogweed, dav1d, uavs3d, and lcms2.

The selected non-`-GPL` MPVKit binaries are described as LGPLv3 by the [MPVKit project](https://github.com/mpvkit/MPVKit), but Lagoon currently has:

- No repository license
- No third-party acknowledgements
- No dependency license inventory
- No bundled license texts
- No corresponding-source or build offer
- No documented relinking mechanism for statically linked LGPL components

This needs a proper software bill of materials and legal review before public distribution. For LGPL static linking, the usual options involve supplying exact source and build information and relinkable application objects, changing to a compliant dynamic-link arrangement, or replacing the dependency. The App Store's signing and DRM model makes this worth reviewing with counsel.

This is a release blocker, not merely an About-screen polish item.

#### 5. OpenSubtitles

The developer API key in the plist is blank, so direct OpenSubtitles use currently expects each user to enter a consumer key. Before version 1.0:

- Confirm that this distribution model complies with the [OpenSubtitles API terms and authentication model](https://ai.opensubtitles.com/docs).
- Establish an appropriate app or developer agreement if required.
- Provide privacy disclosures and attribution.
- Improve the consumer experience.

If that cannot be resolved, ship version 1.0 using Jellyfin's configured subtitle providers and temporarily disable Lagoon's direct fallback.

#### 6. Export compliance

The bundle includes GnuTLS, so Lagoon contains industry-standard encryption outside Apple's operating system. Apple requires the export-compliance questionnaire, and distribution in France may require a French encryption declaration. See Apple's [export-compliance overview](https://developer.apple.com/help/app-store-connect/manage-app-information/overview-of-export-compliance) and [documentation table](https://developer.apple.com/help/app-store-connect/reference/app-information/export-compliance-documentation-for-encryption).

Do not set `ITSAppUsesNonExemptEncryption` to `NO` until this has been answered correctly for every linked library.

#### 7. Content rights and branding

Apple asks whether the app accesses third-party content and whether the developer has the necessary rights. The answer should acknowledge that Lagoon accesses user-provided Jellyfin media and third-party metadata, while explaining that Lagoon supplies no content. Apple documents this under [App Information and Content Rights](https://developer.apple.com/help/app-store-connect/reference/app-information/app-information/).

Also verify:

- Jellyfin brand use against its [branding policy](https://jellyfin.org/docs/project/branding/)
- Seerr/Jellyseerr and TMDB downstream metadata and artwork terms
- OpenSubtitles attribution
- Rights-cleared demo media and screenshot artwork

Lagoon as the product name is good. Avoid presenting it as an official Jellyfin product. Jellyfin's [client listing requirements](https://jellyfin.org/docs/general/clients/) also expect clear licensing and responsible branding.

#### 8. Remote, accessibility, and networking audits

The control design generally follows Apple TV conventions, but the custom scrubber needs real-device testing against Apple's [remote interaction guidance](https://developer.apple.com/design/human-interface-guidelines/remotes), particularly press-before-swipe scrubbing, Back behavior, Play/Pause, and controller consistency.

Before submission, test:

- VoiceOver
- Switch Control
- Reduce Motion
- Increased Contrast
- Dynamic Type on iPhone and iPad
- Subtitle appearance settings
- tvOS focus restoration
- Siri Remote and game controllers
- IPv6-only and NAT64 networks, as required by App Review

## Required before version 1.0

### Release blockers

1. Add and validate privacy manifests for the app and Top Shelf extension.
2. Add `NSLocalNetworkUsageDescription`.
3. Publish a privacy policy and support site; add in-app Privacy, Support, and Acknowledgements links.
4. Resolve LGPL and all third-party dependency obligations; add an SBOM and notices.
5. Resolve OpenSubtitles commercial/distribution, privacy, and key strategy.
6. Complete the encryption export-compliance determination.
7. Fix the OpenSubtitles and Top Shelf Swift concurrency warnings.
8. Repair the failing tvOS UI test and run the deterministic suite cleanly.
9. Add continuous integration for unsigned iOS/tvOS Release builds and unit tests.
10. Perform an external TestFlight.
11. Run a physical playback matrix covering Apple TV generations, iPhones and iPads, HDR and SDR, receivers, HomePods and AirPods, and representative codecs.
12. Test Jellyfin versions, reverse proxies, self-signed and failing TLS, slow remote links, IPv6-only networking, and server outages.
13. Create a signed Distribution archive and pass Xcode and App Store validation.
14. Prepare a rights-cleared reviewer server with working credentials and every reviewable feature enabled.

### Strongly recommended

- Add a manual streaming-quality or bitrate selector for remote servers.
- Add a visible insecure-HTTP warning.
- Introduce String Catalogs even if version 1.0 initially ships only in English.
- Run a dedicated accessibility audit.
- Add MetricKit and establish a crash-monitoring process.
- Increase focused coverage around player fallback, seeking, account migration, cache recovery, and Top Shelf cleanup.
- Update [roadmap.md](roadmap.md) because it still lists several already-completed features.
- Expand [release.md](release.md) from internal TestFlight instructions into an App Store release checklist.
- Reconsider the OS 26 minimum. It simplifies implementation but excludes substantially more devices than Infuse, Streamyfin, the official iOS app, and Swiftfin.

Live TV and offline downloads do not have to block version 1.0 if Lagoon is explicitly positioned as a movie and television library player. Do not market it as a complete replacement for every Jellyfin feature until those gaps are addressed.

Recommended:

- Name: `Lagoon - Home Media Player`
- Subtitle: `A native client for Jellyfin`

## Recommended version 1.0 positioning

Define Lagoon version 1.0 as:

> A premium-quality native Apple client for Jellyfin movie and television libraries, with broad playback compatibility, rich Apple TV integration, and optional Seerr requests.

That scope is already technically credible. Once the privacy, licensing, OpenSubtitles, export-compliance, warning and test, and physical-beta gates are closed, Lagoon can reasonably move from feature-complete beta to a version 1.0 release candidate. The app itself is compelling; the release package around it is what needs finishing.
