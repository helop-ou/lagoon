This addresses A01's residual finding directly: there is no native TLS
implementation left to accept an untrusted certificate, since libavformat no
longer speaks TLS at all and trust is Apple's own system evaluation. It also

has to cover is smaller. And it changes A07's encryption evidence: the app no longer bundles
any non-Apple TLS implementation, which is the ordinary case for an
OS-only-encryption export declaration. None of this is measured or merged
yet — the lead is comparing HLS playback before and after in a separate
write-up, and this paragraph does not close any Gate checkbox below.

## 1. Overall assessment

Lagoon is a capable, unusually broad **late beta for a movie-and-TV Jellyfin client**. Its principal user journey is implemented: connect, authenticate, browse, search, choose a title, play with resume and subtitles, and continue on a later visit. Collections, a unified filtered Library, substantial Seerr integration, multiple accounts, Top Shelf, and a custom native media pipeline take it well beyond an MVP.

The interface is substantially more mature than a shared tvOS layout merely scaled down for phones. The current code has native iOS navigation and controls, adaptive grids and detail actions, independent settings pages, and explicit work for touch, text scaling, and accessibility. tvOS focus handling shows sustained attention to the actual remote experience.

**Feature breadth is ahead of release assurance.** The most consequential findings are:

1. The pinned FFmpeg TLS implementation accepts an untrusted certificate by default, and Lagoon does not enable verification for its native network path.
2. Top Shelf publishing can outlive account switching or logout and republish the outgoing user's content. Account removal and recent-search cleanup also have boundary gaps.
3. Required-reason privacy manifests are absent from both built products, and iOS local-network permission text is missing.
4. Static LGPLv3-or-later dependencies lack a reviewable distribution-compliance package; the encryption declaration needs a documented assessment.
5. The disc parser accepts a metadata-controlled descriptor length that can request approximately 1 GiB in one read, bypassing its separate directory-size cap.
6. Public distribution, support/privacy information, review fixtures, and device acceptance are unfinished or not evidenced in the repository. Selected UI testing has two unresolved failures, with different causes.

These are concrete hardening and release-engineering tasks. Additional Home shelves, Live TV, or another player engine would not resolve them.

There is no defensible single “percent complete”: a required declaration and an optional feature have entirely different effects. The core scope is close; the release gates are not closed.

**Planning estimate, not a delivery promise:** for one developer familiar with this code, allow roughly **4–8 focused weeks** for a deliberately scoped release, including fixes, compliance work, device testing, and at least one feedback/fix cycle. This assumes representative devices are available and the dependency-distribution solution does not require a substantial rebuild or architecture change. Licensing resolution, a transport redesign, or failures on older supported hardware can extend that materially. This is several hardening cycles, not just a version-number change and screenshots.

## 2. Scope, method, and evidence

The audit inventories the complete first-party source tree and examines the app entry point, models, networking and credential stores, account lifecycle, browsing and discovery, player pipeline, disc readers, caches, subtitles, Top Shelf extension, assets, Xcode configuration, package/build scripts, tests, and documentation. Review depth is greatest at trust boundaries, asynchronous ownership, user-visible state changes, and packaging. This is a repository-wide engineering audit, not formal verification of every line or a complete security assessment of upstream native libraries.

Evidence labels:

- **Verified:** observed in a fresh build, test, artifact inspection, or bounded reproduction.
- **Source-confirmed:** behavior or an unsafe interleaving follows from the implementation; no physical-device reproduction was performed.
- **Inference / validation gap:** an architectural concern or missing proof, distinguished from a demonstrated product failure.
- **External gate:** a decision or evidence outside the source tree, such as App Store Connect configuration or distribution rights.

App Store Connect, commercial agreements, private support websites, and a production signed archive were not inspected. Their absence from this audit does not establish that they do not exist elsewhere. No build was uploaded or submitted. Existing internal TestFlight history is acknowledged; it is not equivalent to public-release validation of build 90.

### Reasonable exclusions from 1.0

Live TV/EPG/DVR, offline downloads, music/audiobook/photo-specific browsing, SharePlay, cloud preference sync, Spotlight/App Intents, extensive localization, and full disc menus are not necessary for a useful movie-and-TV release. Offline downloads are distinct from the transient cache, which deliberately does not create saved media.

Keep the promise narrow and accurate. English-first support and modern Apple OS minimums are legitimate scope choices. The OS 26 requirement limits the audience but does not itself make the app incomplete or noncompliant.

## 4. What is good

### Native interaction and visual structure

[DesignSystem.swift](../Lagoon/Views/Components/DesignSystem.swift) centralizes spacing, sizing, motion, and branding. [AdaptiveLayout.swift](../Lagoon/Views/Components/AdaptiveLayout.swift) includes scaled posters, width-aware grids, and alternatives for crowded detail actions. System-semantic controls carry much of the interaction.

tvOS work addresses focusable error/loading states, rail padding, restoration after playback, stable navigation identity, and the distinction between a light Siri Remote touch and Select. Recent refresh work associates reconciliation with the visible root instead of indiscriminately refreshing hidden screens.

The fresh iPad portrait Home smoke showed coherent native tabs, readable hero text, and proportionate rails. This supports the layout direction but cannot replace complete iPad testing.

### Data and session design

Value-based DTO equality, defensive decoding, explicit tick conversion, account-scoped preferences, and pagination generations address real server/client edge cases. The playback-report ledger makes returning to browsing wait for the relevant stop report, reducing resume-state races.

Draft account setup uses a separate client and accepts an account only after successful authentication. Passwords are not retained as remembered credentials. Jellyfin/Seerr persistence includes Keychain error handling and readback verification. Top Shelf consumes local snapshots without receiving Jellyfin credentials or making authenticated server requests.

These are sound foundations. The account findings concern incomplete lifecycle enforcement around them.

### Playback engineering

The implementation contains bounded queues, compressed read-ahead, sparse caching, decoder worker policy, GPU delivery ordering, fallback by failure type, teardown diagnostics, and timing instrumentation. It makes purposeful use of Apple's sample-buffer APIs while retaining FFmpeg container flexibility.

The dav1d work is well evidenced: a repository-owned rebuild script, assembly verification, documented diagnosis of a correct-but-slow upstream build, and subsequent hardware acceptance. Performance notes also retain retracted comparisons and measurement conditions.

### Dependencies, tests, and documentation

The mpv/MoltenVK/libplacebo stack is gone. The local package pins checksums and limits the dependency graph. Approximately 27 MB per unsigned device bundle is modest for the media stack, though not an App Store size measurement.

Unit tests cover meaningful parsing, negotiation, timeline/order behavior, filters, permissions, subtitles, and reporting logic. Both platform runs pass. DEBUG regression hooks provide useful introspection.

[Architecture](architecture.md), [playback](playback.md), [API notes](jellyfin-api.md), [design system](design-system.md), [roadmap](roadmap.md), and [release documentation](release.md) preserve non-obvious decisions. The roadmap distinguishes implementation from hardware acceptance. Continue maintaining that distinction.

## 6. Prioritized findings

These are release-planning priorities, not CVSS scores:

- **P0:** fix immediately before expanding distribution.
- **P1:** close before public 1.0, or remove the affected optional capability from scope.
- **P2:** material quality/maintainability issue; fix before launch where practical or explicitly accept a narrow limitation.
- **P3:** later enhancement, generally discussed under scope rather than treated as a blocker.

### A01 — P0: native FFmpeg HTTPS does not verify certificates by default

**Follow-up, September 8 (spike branch):** libavformat has no network stack
left to misconfigure — every HTTP(S) open now goes through
`FFmpegNetworkTransport` over URLSession, whose ordinary system trust
evaluation rejects self-signed, expired and wrong-host peers. Not yet
measured or merged; see the "Transport follow-up" paragraph above.

**Evidence: verified dependency behavior plus source-confirmed app configuration.**

[FFmpegDemuxer.swift](../Lagoon/Views/Player/SampleBuffer/FFmpegDemuxer.swift), lines 295–389, sets timeout/reconnect options and opens input without setting TLS verification. The default release HLS path uses libavformat's own HTTP/TLS implementation. Experimental HLS caching also leaves mutable manifest I/O on the native path. Direct cached media uses URLSession, a different transport path.

A standalone probe linked against the macOS arm64 slice from the same pinned xcframework set reported:

```text
version=n8.1.2
license=LGPL version 3 or later
tls_verify_default=0
```

Calling `avio_open2` against a temporary local HTTPS endpoint with a self-signed certificate for the wrong hostname returned `open_result=0`. System curl rejected the endpoint with certificate error 60. The probe queried the actual TLS AVOption default, rather than relying on current website documentation, whose defaults can differ from this pinned backend/build.

**Impact:** an attacker able to intercept this traffic can impersonate a media endpoint. Playback URLs can contain Jellyfin access tokens, making this a credential-exposure issue too. This does not imply URLSession password login disables certificate checks. The live probe used the dependency's macOS slice, not a physical Apple TV; the iOS/tvOS artifact paths must be included in fix verification.

**Fix:** configure certificate and hostname verification with a valid trust store for every native TLS open, including children and reconnects, or move those requests to an audited system-networking path. Enabling a flag without checking platform roots and option propagation is insufficient.

**Exit criterion:** device-artifact integration tests reject self-signed, expired, and wrong-host certificates and accept valid trusted certificates. ### A08 — P1: malformed UDF descriptor length bypasses the directory resource cap

**Evidence: bounded reproduction using unchanged parser source.**

[UDFVolume.swift](../Lagoon/Views/Player/SampleBuffer/Disc/UDFVolume.swift), lines 189–205, masks a long allocation descriptor length to 30 bits and passes the larger of that value and 2048 to its reader. The later directory-content cap does not bound this earlier descriptor read.

A fixture-based probe called the entry reader with length `0x3fffffff`. It requested **1,073,741,823 bytes**, despite an image size of **778,240 bytes**. ## 7. Privacy, storage, and trust boundaries

No advertising or analytics SDK was found in the reviewed dependency graph. That is a privacy advantage, but it does not alone determine the App Store privacy label. Apple distinguishes on-device processing from off-device data retained beyond servicing a request, including applicable third-party practices. Establish who receives and retains the data before choosing “Data Not Collected.” Ordinary authentication is not, by itself, cross-app tracking that requires ATT. ### Security positives and remaining verification

Positive controls include Keychain token storage, no remembered passwords, no bundled server administrator key, same-origin checks when adding playback authentication, optional linked services, and a credential-free extension. The app-group entitlements match between app and extension.

The main trust boundary is not just JSON from a server: it includes native demuxers, manifests, images, subtitle files, and disc filesystem metadata. TLS validation, response limits, and parsing budgets therefore matter even for a client of a user-selected server.

Additional release checks, without treating them as already-proven vulnerabilities:

- Exercise cross-origin and HTTPS-to-HTTP redirects for API, playback, HLS children, images, and subtitle downloads. Confirm credentials are never forwarded to an unintended destination.
- Inspect retained diagnostic strings and exported support logs for query tokens, cookies, usernames, and server addresses. Some Top Shelf errors are explicitly logged as public; error contents need review.
- Confirm cache purge on exit/account transitions, OS eviction, low storage, process termination, and subsequent restart. “Transient” should remain true in failure paths.
- Decide whether the existing Keychain after-first-unlock accessibility class and migration/backup semantics match the product's intended account behavior; this is a design decision, not an automatic defect.
- Record exact dependency versions, source provenance, and a process for upstream security advisories. Pinned checksums prevent silent artifact changes; they do not establish that an artifact is secure or license-complete.

### Testing quality

The unit suite is a meaningful asset, not mere line-count padding. It exercises data normalization, filters, permissions, byte layouts, timelines, fallback/report behavior, and other deterministic logic. However, its short simulator execution cannot demonstrate sustained decode throughput, thermal performance, display matching, or real remote/route behavior.

The two shared schemes serve different purposes: the main Lagoon scheme runs unit tests; LagoonHardwareRegression includes tvOS UI work. There is no corresponding iOS/iPadOS UI-test target and no checked-in CI workflow discovered in the repository inventory.

Recommended test investments are specific to the findings:

1. Account transition/credential cleanup and delayed Top Shelf publication.
2. TLS failures and HLS nested-request transport policy using controlled endpoints.
3. Descriptor bounds, truncated media, and request-size caps.
4. Auth expiration distinct from outages.
5. Same-item optimistic-state reconciliation.
6. Deterministic navigation and confirmed direct/HLS fixture selection.
7. A small iOS UI lane for onboarding, library/search/detail, player controls, and account switching.

Do not chase a coverage percentage by testing trivial view structure. Add tests at contracts where a failure has a meaningful user or security consequence.

### Performance and operational readiness

The engine has unusually useful local performance instrumentation. Its bounded queues and repaired renderer-pump behavior are positive. The successful direct-play smoke establishes short sustained playback on the simulator; it does not establish full-film stability or thermal behavior.

Before release, measure:

| Workload | Evidence needed |
| --- | --- |
| Long direct-play movie | Stable memory, audio/video sync, seek recovery, clean teardown after 1–2 hours |
| HLS with several segment/reconnect cycles | Verified transport method, sustained progress, no child-I/O leaks |
| Software 4K AV1 on supported Apple TV | Comparable media window, repeat runs, frame-loss/audio data; build tied to acceptance |
| Software decode on iPhone/iPad | Energy/thermal behavior and fallback under sustained load |
| Large Home/library | Cold/warm first-content time, scrolling smoothness, cancellation, bounded image work |
| Low storage / cache eviction | Predictable recovery, no blocking startup or uncontrolled growth |
| Top Shelf artwork composition | Time/memory during first publication and suspension; generation-safe recovery |
| Repeated start/stop / episode handoff | No accumulating engine, renderer, file descriptor, or GPU resource ownership |
| Background/foreground and route changes | Stable user state, correct pause/resume policy, no stale system controls |

Use the repository's existing benchmark discipline: comparable scenes and time windows, multiple runs, and an undisturbed simulator/device. Do not compare unrelated single runs.

For post-release support, retain app symbols, dependency identities, and reproducible build inputs. The release documentation acknowledges missing native-library dSYMs; plan how native crashes will be triaged. Define who reviews Xcode Organizer/TestFlight crashes and how users report a failing file/route without exposing credentials. A commercial analytics/crash SDK is not necessary to establish that process.

## 9. Product and design work that matters most for 1.0

The highest-value product improvements are reliability at the edges of existing journeys:

- **Connection:** recognizable server URL, secure/plain-HTTP state, useful LAN-denial and auth-expiry recovery.
- **Household accounts:** no previous viewer's search/shelf/session residue; clear differences between switching, forgetting, and signing out.
- **Playback errors:** distinguish source incompatibility, network failure, server transcode failure, and subtitle failure; retain resume state and a useful retry path.
- **Remote streaming:** a simple quality choice or an explicit automatic-selection limitation.
- **Accessibility:** verify complete common tasks, including captions and player exit, across actual supported device classes.
- **Support:** privacy, contact, acknowledgements, supported formats, and server setup available without a functioning server.

The current interface has a coherent identity and strong native structure. It does not need a visual redesign before 1.0. The confirmed refresh alignment issue is a localized polish/regression problem. Avoid replacing established focus and adaptive-layout behavior merely to simplify source code.

The public settings surface deserves one deliberate pass. Playback HUDs, frame-loss tooling, decoder switches, and experimental cache controls help TestFlight diagnosis, but a new viewer should not need to understand those internals. Keep useful advanced diagnostics clearly separated, decide which switches ship, reset obsolete experimental defaults, and document any supported diagnostic workflow. Their presence is not automatically an App Review violation.

1. **Freeze feature expansion.** Agree the movie/TV scope and truthful format/integration claims.

### Bounded security/robustness reproductions

**TLS:** compile a small C probe against the pinned Libavformat/Libavutil and required transitive frameworks. Query the class returned by `avio_protocol_get_class("tls")` with `av_opt_find` for `tls_verify`, using `AV_OPT_SEARCH_FAKE_OBJ`, and print its default integer alongside version/license. Call `avio_open2` against a loopback HTTPS server with a generated self-signed wrong-host certificate. Compare with a system-trust client. The audit's exact results are recorded under A01.

**UDF:** compile unchanged DiscImage/UDFVolume code with the existing synthetic disc-fixture builder and a guarded byte source. Let ordinary reads access the fixture; log and throw before any read above the guard budget. After mounting, call the file-entry reader with a 30-bit maximum descriptor length. The audit observed the oversized request under A08 without allocating it. This proves an unbounded request contract, not a measured device crash.

**URL probing:** run the actual candidate construction for schemeless reverse-proxy input. The default-port variant places 8096 in the path; a complete explicit HTTPS URL remains valid. A13 describes the affected case.

### Corrections to the previous audit

This document supersedes the following stale or overly broad conclusions:
